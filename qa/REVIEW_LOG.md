## R2 — QA agent: odd combinations (APK as installed after R1; fresh mock :9020; second client = Python WSClient)
- [Q2-1] [major] [clip/state-sync] The app cannot handle the protocol's "opened clip disappeared / closed" signal: server sends `sec clip` with `d:null` and the app shows a warning toast "Bad 'clip' section: Expected JsonObject, but had JsonNull as the serialized body of..." and keeps the stale editor. Consequences: (a) the Clip editor's "Close" button never closes the editor (clip.close → clip:null rejected); (b) deleting the open clip from another client (or Session menu) leaves the editor showing the deleted clip; (c) switching focus to another track keeps showing the previous track's clip (e.g. Vocals "Vox A" waveform while focused on Drums) instead of the "Open a clip on <track>" list. Repro: open a clip (Session long-press → Edit clip), tap Close, or `slot.delete` it from another client, or change track. Evidence: qa/screens/r2_02_deleted_open.png, r2_03.png, r2_15_pre.png. Status: fixed(493f60d)
- [Q2-2] [minor] [session/take] TAKE button is enabled on group / master / return tracks; tapping gives toast "track cannot record" → disable (or hide) TAKE and the empty slot grid for non-recordable tracks (master shows empty "No slots" under a live TAKE button). Evidence: qa/screens/r2_12_takegroup.png, r2_13_master_take.png. Status: fixed(493f60d)
- [Q2-3] [minor] [layout/font1.3] fontScale 1.3 portrait: scene-name column in Session is too narrow, names collapse to "Ve…", "Ch…", "Ou…" (Verse / Chorus / Outro indistinguishable; Verse vs Verse 2 identical). Everything else fits. Evidence: qa/screens/r2_05_font_sess.png. Status: fixed(493f60d)
- [Q2-4] [minor] [waveform] Loop/start markers dragged in the waveform end up at arbitrary fractional beats (loop_start 1.40625) – no snap to beat/grid. Also the end-of-clip "E" handle sits at the very screen edge in portrait, so dragging it triggers Android's back gesture (app returned to Connect screen). → inset handles/ hit areas or add a bigger grab zone. Evidence: qa/screens/r2_09_loopdrag.png. Status: fixed(493f60d)
- [Q2-5] [nit] [shell] App always launches to the Connect screen (no auto-reconnect to the last host); Back at the shell root silently drops to Connect/disconnects without confirmation. Status: fixed(493f60d)
- [Q2-6] [nit] [mock] `auto_arm` (exclusive arm) is true but taking on Keys then Vocals leaves BOTH armed in the mock; real Live would disarm the first. Not an app bug.
- Works well: concurrent edits from a second client (tempo, mute, vol, track rename incl. 50-char name) appear in the app within a tick; long track name ellipsized everywhere, full in Mix; take on track A then switching to B and taking there records both without crosstalk (verified per-track on server); focus on Group/Return/Master renders every tab (disabled Arm/+MIDI on group, Limiter on master); fast chain of 15 slot taps → server ended in exactly the last-fired state; rotating mid-clip-edit keeps the clip, selection and waveform; rotation drops open dialogs (acceptable); app reconnects to the mock automatically after the old mock process went away and came back (state reset to defaults, focus returns to first track).

## R3 — QA agent: unintended use

- [Q3-2] [minor] [connect] Invalid host strings (":", "host:abc", "10.0.2.2:99999", "10.0.2.2:-5", blank) just leave the Connect button doing nothing — no validation message. Status: open

On reconnect state is correctly replaced (stale actions are not replayed — good). → dim/disable controls while disconnected. Evidence: qa/screens/r3_04_down_actions.png. Status: open
- [Q3-4] [minor] [shell/layout] The "Connection lost – retrying … Disconnect" banner is inserted at the top and pushes the entire UI down ~85px, and removes it again on reconnect → layout jump (violates "no sliding UI"); an overlay/in-bar indicator would not move controls. Evidence: qa/screens/r3_02_mockdown.png. Status: open
- [Q3-5] [major] [nav] Android Back from ANY tab other than Session (Mix, Dev, Arr, More, Clip…) immediately leaves the shell to the Connect screen and drops the connection; a second Back exits the app. Back never first returns to Session, and a single accidental Back mid-session disconnects. - [Q3-6] [minor] [validation] Numeric input handling inconsistent: tempo dialog silently refuses -5 / 99999 / "" / "abc" / "1e3" and stays open with no message (20 accepted; range hint "20-999" is shown, good); clip Start dialog closes silently on "-5"/"abc"; clip Start "9999.9.9" is accepted and sets start_marker=40002 beats while end_marker=256 (start > end, no clamp; real Live would reject). → clamp/validate against clip length/loop and show an error.
